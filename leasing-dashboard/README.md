# 週次リーシングダッシュボード

不動産ポートフォリオの週次リーシング状況を表示する、静的な HTML / CSS / JavaScript のダッシュボードです。
外部サーバー・データベース・外部ライブラリ・CDN・解析 SDK は使いません。入力データはブラウザ内でのみ処理し、外部へ送信しません（`index.html` の Content-Security-Policy で外部への接続を禁止しています）。

入力は Microsoft 365 Copilot が作成した次の中間データだけです。仕様は `dashboard_spec.md`（提供資料）に従います。

| ファイル | 内容 |
|---|---|
| `dashboard_data.json` | 対象週のメタデータ・物件明細・アラート・検証サマリー・ファイル一覧 |
| `property_master.csv` | 物件マスター（物件名・SPC・AM・PM の正） |
| `validation_report.csv` | ファイルごとの処理結果 |

## 使い方

### 1. データを置く

`data/` フォルダに上の 3 ファイルを置きます。ファイル名は固定で、日付は含めません。
`data/` の中身は `.gitignore` によりリポジトリに含まれません。

### 2. 起動する

Node.js がない PC では、`index.html` をダブルクリックで開きます。その画面に週報 Excel・物件マスターをドラッグ＆ドロップすると表示されます（`data/` フォルダは自動では読めません）。

Node.js 18 以上がある場合は、次のコマンドで起動すると `data/` フォルダのデータも自動で読み込みます。

```sh
./start.sh            # macOS / Linux
start.bat             # Windows
npm start             # どちらでも可
```

起動時にデータ検証を実行し、`http://127.0.0.1:8080/` でダッシュボードを配信します。待ち受けは自分の PC（127.0.0.1）のみです。

- 架空サンプルで動作を確認する: `./start.sh --data sample_data`
- ポートを変える: `./start.sh --port 8090`

Node.js がない場合は `index.html` をブラウザで直接開き、右上の「ファイルを選択」で 3 ファイルを選ぶ（またはドラッグ＆ドロップする）と表示できます。ファイルはブラウザ内で読むだけで、送信しません。

### 3. 毎週の更新（ドラッグ＆ドロップ）

その週の週報 Excel（複数可）を、ダッシュボードの画面にドラッグ＆ドロップするだけで更新されます。コードの変更は不要です。

- 週報はブラウザ内で解析し、前回までのデータに今回の週を追加します（前週比・週次推移に使用）。ファイルは送信しません。
- 取込結果・物件マスター・対応表はこのブラウザ内（IndexedDB）に保存され、次に開いたときも表示されます。`data/` フォルダの方が新しい週のデータを持っていれば、そちらを表示します。
- **物件マスター（`property_master.csv`）もドロップで反映できます。** 直前に取り込んだ週報は、新しいマスターで紐付けし直します。マスターに列（TMK など）を足すと、その列での絞り込みが自動で増えます。
- **対応表（`source_mapping.csv`、列: `file_name_pattern,project_number`）をドロップすると、ファイル名だけでは物件を特定できない週報を指定できます。**
- 物件に紐付かなかった週報や、データのない物件は「データ検証」タブに一覧で出ます。
- 共有用に、取込結果（`dashboard_data.json`・`validation_report.csv`）を「データ検証」タブから保存できます。`data/` に置くと、他の人も同じ内容を表示できます。
- ブラウザの保存内容は「データ検証」タブの「ブラウザに保存したデータを削除」で消せます。

`data/` のファイルを直接差し替えて「データ再読込」を押す方法も使えます。

### 4. SharePoint で共有する（Excel レポート）

画面右上の **「SharePoint用Excelを保存」** で、表示中の基準週の内容を `leasing_dashboard.xlsx` に書き出します。SharePoint の同じフォルダに同じ名前で置き換えると、URL を変えずに毎週更新できます。閲覧者は Excel for the web で開き、見出しの ▼ で担当者・TMK などを絞り込めます。手順・SharePoint ページの作り方・Copilot への質問例は `SHAREPOINT_GUIDE.md` を参照してください。

- シート: サマリー、物件一覧、空室率、長期空室、申込・解約、条件変更、工事、アラート、対応事項、データ検証、データのない物件
- 表示ルールはダッシュボードと同じ（「データなし」は 0 にしない、比率は小数第 1 位、金額は万円、暫定の明示）。個人情報らしい項目は出力しない
- 画面の絞り込みに関係なく全物件を書き出す（絞り込みは Excel 側で行う）
- コマンド: `npm run excel`（`data/` から `output/leasing_dashboard.xlsx` を作成。`--period YYYYMMDD` で基準週を指定）。`output/` はリポジトリ対象外
- 外部ライブラリは使わず、`xlsx-writer.js` で Excel を作成（Excel・LibreOffice・openpyxl で開けることを確認済み）

- 画面上の対象週には `report_metadata.source_period` を表示します。
- 物件明細に複数週の `report_date` があれば「基準週」で切り替えられ、前週比・週次推移に使われます。
- `dashboard_data.json` が不正な JSON の場合は更新せず、前回正常に読み込んだデータを表示したまま警告バナーを出します（前回データはこのブラウザ内の IndexedDB に保存。外部には送りません）。

## Microsoft 365 Copilot で編集する

Microsoft 365 Copilot（法人版）に指示して編集できるよう、次のものを用意しています。手順と指示文の例は `COPILOT_GUIDE.md` を参照してください。

- `AGENTS.md`（同じ内容の `copilot/knowledge_AGENTS.txt`）: 守るべきルールとファイルの役割
- `copilot/agent_instructions.txt`: Copilot の編集用エージェントの「指示」に貼る文（8,000 文字以内）
- `selftest.html`: Node.js がなくても、ブラウザで開くだけで主要なルールを確認できる自己診断ページ。Copilot の回答を反映したあとに開き、すべて OK になることを確認します。

## 表示・計算ルール

| ルール | 実装 |
|---|---|
| null | 「データなし」と表示。0 に置き換えない。合計対象がすべて null なら合計も null |
| 0 | 「0」と表示（確認済みの 0） |
| 文字が混入した数値 | 推測で変換せず「数値不正」と表示し、集計から除外 |
| 比率 | 小数第 1 位（例: 91.6%）。前週比は pt |
| 金額 | 入力は円とみなし、既定は万円で表示（`config.js` の `display.moneyUnit` を `'yen'` にすると円）。見出しに単位を表示 |
| データ確度 | high＝緑・medium＝黄・low＝赤（ラベル付きで色だけに頼らない） |
| 暫定 | low や確度不明のデータ、欠損、重複・未紐付けの除外、読取失敗ファイル、元データの暫定指定のいずれかがあれば「暫定」と表示し、理由を併記 |
| 物件名 | `property_master.csv` を正とする。JSON 側の名称と違えば警告 |
| 結合キー | Project #（全角・前後空白は正規化して比較） |
| 稼働率 | `occupied_units / total_units`。いずれか null または分母 0 なら null。元データ値との差が 0.0001 を超えたら分子・分母・元値・計算値・差を記録 |
| 申込反映後稼働率 | `occupancy_after_application_calculated` に値があり（元データ側が算出を許容）、稼働・申込・総戸数が揃う物件のみ `(occupied + application) / total` |
| ポートフォリオ稼働率 | `sum(occupied) / sum(total)`。重複候補・マスター未登録は除外 |
| 前週比 | 両週とも値がある物件同士で比較（欠損を 0 とみなさない）。比較物件数を表示 |
| 判定不可 | 判定に必要なデータがないアラートは「判定不可」と表示し、0 件と区別 |

申込取消は仕様に専用列がないため、任意列 `application_cancel_count`、またはコメント中の語句（`config.js` の `alerts.cancellationKeywords`）で検出します。AD・FR は単位が仕様で未定義のため、元データ単位のまま表示します。

## 週報 Excel の取り込み

PM ごとに様式の異なる週報 Excel（.xlsx / .xlsm）を直接読み、`dashboard_data.json` と `validation_report.csv` を作ります。外部ライブラリを使わず、Excel ファイルは読み取りのみで変更しません。

```sh
# PC で（Node.js 18 以上）。週報フォルダ直下の Excel を解析して data/ に出力
node scripts/ingest-weekly.js --in <週報フォルダ> --out data
```

- ブラウザだけで使う場合は、ダッシュボード右上の「ファイルを選択」で週報 Excel と `property_master.csv` をまとめて選びます。解析はブラウザ内で行い、送信しません。結果は「データ検証」タブから保存できます。
- 前回の `data/dashboard_data.json` があれば、過去の週を引き継いで前週比較に使います（`config.js` の `ingest.historyWeeks`、既定 12 週）。

### 対応している様式

様式はシート名と見出しの文字で判定し、行・列の位置は固定していません。

| 様式 | 判定の目印 | 読む内容 |
|---|---|---|
| A 週報型 | 「週報」シートに「現況」「部屋番号」の見出し | 住戸明細（現況・解約日・退去日・原復完了・募集条件・申込日）、週次の問合せ・案内・申込・キャンセル、リーシング活動（今週分）、基本情報の部屋一覧 |
| B 営業活動週報型 | 「営業活動報告書」「【募集中・解約予定住戸】」 | 総戸数、日別の案内・申込・契約件数、募集中・解約予定住戸、進捗状況（申込日）、条件変更等（今週分） |
| C リーシング報告書型 | 期間名のシート（例: 2026.1.5-2026.1.11）と「現募集中」 | 期間別シートごとの集計欄（空室数・反響・内見・新規申込・申込中・キャンセル）、現募集中の住戸、部屋概要の部屋数、＜申込＞＜解約予告＞キャンセル欄 |
| D Action Points型 | 「List」シートに「Target Due Date」 | 対応事項（物件・期日・優先度・状況・カテゴリ・対応内容・最新状況）。リーシングの数値には合算しない |

### 解析のルール

- **数式の計算結果がない場合:** 提供された様式サンプルは、すべての数式で計算結果がファイルに保存されていませんでした。そのため、集計・稼働率・空室日数は住戸明細などの元の値から再計算します。元ファイルの稼働率（`occupancy_rate_source`）は `null` とし、再計算値（`occupancy_rate_calculated`）と分けて保持します。再計算した項目は「読取不能項目」に記録し、データ確度は medium にします。
- **空室の定義:** 様式ごとのシートの定義に従います。
  - A は As-is 稼働率の定義に合わせ、空室・原復中・申込を空室に数えます（募集止め・契約済・FR は数えない）。
  - B は状況が空室・申込の住戸を空室に数えます。
  - C は集計欄の空室数を使います。
- **空室日数:** A のシートの数式（基準日 − 解約日）に合わせ、解約日を空室開始日とします。解約日がない場合は退去日を使います。
- **週の区切り:** 基準日・対象期間は日曜締めの週にそろえます（`ingest.weekEndDay`）。そのため、月曜付けの報告日も前日の日曜の週として扱います。
- **重複排除:** C の期間別シートは過去の申込・解約予告・キャンセルを累積で再掲するため、前週シートとの差分だけを今週の新規とします。
- **合算しない:** 同じ物件・同じ週に複数のファイルがある場合は、合算せず「リーシング報告書型 → 週報型 → 営業活動週報型」の順に1つを採用し、重複候補として記録します。同じ内容のファイルの二重読込は、2件目を重複として扱います。
- **推測しない:** 現況が空欄の住戸は推測で補わず、住戸明細から除外して警告します。年のない日付（例: 9/23）や、文字の入った数値欄は使いません。
- **出力しない項目:** 申込者名・契約者名・保証会社・仲介会社・属性・年収・申込内容・内覧コメント・メモ欄は出力しません。
- **物件（Project #）の特定:** 次の順に照合します。
  1. 対応表 `data/source_mapping.csv`（`file_name_pattern,project_number`）
  2. ファイル名に含まれる物件マスターの物件名（最長一致）
  3. ファイル内の物件名

  ファイル名の照合では、物件名の前後が括弧・空白・数字などの区切りのときだけ一致とします（例: 「大岡山Ⅱ」の週報は「大岡山」に、「南馬込」の週報は「馬込」に紐付けない）。多くの物件に共通する接頭語（シリーズ名など）はマスターから自動で見つけ、外した名前でも照合します。どれにも当たらない場合は未紐付けとし、数値には含めず、候補と理由を「データ検証」に表示します。

## 住戸明細（units）

`dashboard_spec.md` の物件単位のデータに加えて、`dashboard_data.json` に任意で `units` 配列を入れると、住戸単位の動きを表示します。`units` がない場合も他の画面はそのまま動き、住戸単位の画面は「住戸明細なし」と表示します。項目の定義は `sample_data_schema.json` の `units` を参照してください。

```json
"units": [
  {
    "report_date": "2026-10-19", "project_number": "P-001", "unit_number": "302", "layout": "1K",
    "leasing_status": "application", "vacancy_start_date": "2026-09-20", "application_date": "2026-10-17",
    "asking_rent": 128000, "common_fee": 8000, "ad": 1, "fr": 0, "deposit_months": 1, "key_money_months": 1,
    "work_type": null, "work_end_date": null, "data_confidence": "high"
  }
]
```

| 知りたいこと | 判定方法 |
|---|---|
| どの住戸の空室期間が長いか | 空室開始日（退去日）から基準日までの日数。開始日がなければ元データの `vacancy_days`。`config.js` の `alerts.longVacancyDays`（既定 90日）以上を「長期」 |
| どの物件の空室率が高い・上がったか | 物件ごとの 空室戸数 ÷ 総戸数 と前週差（pt） |
| どの住戸に新しく申込・申込取消・解約が入ったか | 申込日・申込取消日・解約通知日が「今週」（前回の基準日の翌日〜今回の基準日）に入るもの。日付がない場合は、前週の同じ住戸からの状態変化（空室→申込あり、申込あり→空室、入居中→解約予定）で判定 |
| どの住戸の賃料条件が変わったか | 前週の同じ住戸と比べて、募集賃料・共益費・AD・FR・敷金・礼金のうち値が変わった項目。片方が null の場合は変更とみなさない |
| どの住戸がリノベ中・原状回復中で、いつ終わるか | 工事種別があり完了日がない住戸。完了予定日までの残り日数、完了予定日を過ぎていれば「完了予定超過」。今週完了した工事も表示 |

検証: 住戸の重複、住戸番号なし、マスター未登録、不明なステータス、日付の形式不正、空室開始日と空室日数の食い違い、住戸明細の未入居住戸数（空室・申込あり・契約済）と物件の空室戸数の不一致を「データ検証」に表示します。

Copilot で `dashboard_data.json` を作る際は、各週報の住戸一覧（空室表・募集図面一覧など）から上の項目を `units` として出力するよう指示してください。値が読み取れない項目は推測せず `null` にし、入居者名・申込者名・連絡先は出力しないよう指示してください。

## プライバシー

- 列名が個人情報を示す列（tenant、applicant、guarantor、email、phone、入居者、申込者、氏名 など。`config.js` の `privacy.deniedFieldPatterns`）は読み込みません。
- 表示する文字列のメールアドレス・電話番号・URL・社内パスは「［非表示］」に置き換え、ファイル名はフォルダ部分を除いて表示します。
- 自由記述中の個人名は機械的に判別できません。AM・PM 列やコメントに個人名を入れないよう、中間データ作成時にご注意ください。
- CSV 出力はコメント等の自由記述を含めません。

## データ検証スクリプト

```sh
./validate.sh                      # data/ を検証
./validate.sh --data sample_data   # 別フォルダを検証
./validate.sh --json               # JSON で出力
./validate.sh --strict             # 警告も NG 扱い
```

入力ファイルは読み取りのみで、書き換えません。終了コードは 0＝OK、1＝エラーあり、2＝ファイルなし。
「公開条件」は仕様 8 章に従い、JSON が解析でき、ファイル件数が突合し、全ファイルに検証行がある場合に満たします。

## テスト

```sh
npm test               # 単体・結合テスト（node:test、外部依存なし）
npm run test:browser   # ブラウザ確認（Playwright がある環境のみ。なければスキップ）
```

Node.js がない場合は `selftest.html` をブラウザで開きます（表示ルール・検証・集計・住戸・マスター・週報 Excel の解析・SharePoint 用 Excel の書き出し・個人情報の除外など 24 項目）。自己診断に埋め込む架空の Excel は、`node scripts/build-selftest-fixtures.js` で更新します。

自動テストの対象:

- JSON 構文（不正 JSON の検出と位置表示、BOM、構造不正）
- Project # の重複（マスター内・同一週の明細、全角の正規化）

- 同一ファイルの二重読込（内容ハッシュ、ファイル一覧・検証レポートの重複）

- 週報 Excel の解析: 様式 A〜D の判定と抽出、計算結果のない数式の扱い、期間別シートの差分による重複排除、同一ファイルの二重読込、同じ物件・週の別様式を合算しないこと、現況が空欄の住戸を推測しないこと、個人情報の列を出力しないこと、物件の紐付け、前回データの引継ぎ、元ファイルを変更しないこと（フィクスチャは `tests/fixtures/make_weekly_xlsx.py` で生成した架空データ）

- Copilot 向けガイド（AGENTS.md・COPILOT_GUIDE.md・エージェントの指示文）に書いた関数名・設定名がコードに実在すること、指示文が 8,000 文字以内であること、自己診断ページの埋め込みデータがフィクスチャと一致すること

## 元ファイルを読み取れなかった週の表示

中間データ作成時に元ブックの内容を取得できなかった場合（`properties` が 0 件、`portfolio_summary.status` が `not_calculated`、ファイルがすべて `failed` など）でも、ダッシュボードは数値を推測・補完しません。

- 戸数・稼働率などの集計値は「データなし」（0 とは表示しない）
- 前週比較が必要なアラートは「判定不可」
- 読取失敗ファイルは件数から消さず、アラートとデータ検証に全件表示
- 未算出の理由（`portfolio_summary.reason`）をバナーに表示

`tests/fixtures/all_failed/` は、この状態を再現した架空データです。元ブックの内容を取得できた中間データに差し替えれば、そのまま数値が表示されます。
